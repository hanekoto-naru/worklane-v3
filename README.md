# Worklane

個人用のローカル業務管理Webアプリです。自分のタスク、依頼したタスク、確認事項、関係者、目標・施策を管理します。検索・絞り込み・優先度・期限管理に対応し、ライトモードの一覧と編集モーダルで操作します。

React / TypeScript / Vite、CSS Modules、Tabler Icons、Zodを使用します。データベース・認証・外部APIはありません。関連URLは登録・編集・表示のみで、アプリから外部サイトへ移動しません。

## 必要な環境

- Node.js 22.23.2以上の22系と付属npm。別メジャーの動作は未検証です。
- インストール済みGoogle Chrome。File System Access APIとWeb Locks APIが必要です。対応する最低Chromeバージョンは未確定です。
- 実フォルダ試験の手順はmacOS向けです。

## インストールと起動

以下の `<repository-url>` は取得元のリポジトリURLに置き換えます。

```sh
git clone <repository-url> worklane
cd worklane
npm ci --ignore-scripts
npm run build
npm start
```

Chromeで **http://127.0.0.1:4173/** を直接開きます。`localhost`表記では開きません。本番サーバーはNode.js標準モジュールだけで動作し、依存の取得・ビルドは自動実行しません。4173番が使用中なら停止します。既存プロセスは自動終了しません。

終了前に「保存済み」を確認し、タブを閉じてサーバーのターミナルでCtrl+Cを押します。通常の起動は `npm start` です。

依存導入にはnpm registryへの通信が必要です。`.npmrc` はインストール時スクリプトを無効にします。導入に失敗した場合は、設定を解除する前に原因を確認してください。

## 開発・テスト

```sh
npm run dev -- --host 127.0.0.1
```

開発はダミーデータのみで行います。Vite開発サーバーを業務運用に使用しません。

`npm run build` はTypeScriptチェックを含みます。自動テストと実ファイル試験の手順は [TESTING.md](TESTING.md) を参照してください。

## JSON保存と復元

ソース・Git・クラウド同期対象から独立した専用フォルダをChromeで選択します。初回はデータがない状態で起動します。空フォルダでは確認後に空の正本を作成します。

```text
worklane/           ソースコードとビルド
worklane-data/      別フォルダとして選択
  data.json        唯一の正本
  backups/         更新前の正常なJSON
  recovery/        破損正本を復元する際の退避
```

- 編集確定後に自動保存し、書き込み内容の照合後に保存済みと表示します。
- 再読み込み・Chrome再起動・権限失効後は同じフォルダを再選択します。ハンドルと業務データをブラウザーストレージへ永続保存しません。
- 更新前に正常なJSONをバックアップします。バックアップ作成失敗時は正本更新を止めます。画面の「バックアップ」から選択・確認して復元できます。
- 保存失敗・競合時は画面内の未保存変更を保持します。原因を確認して再試行するか、別の空フォルダへ退避します。保存せずにブラウザーを終了するとメモリの変更は失われます。
- バックアップの自動削除はしません。一覧走査は2,000項目までです。空き容量を監視し、整理前に別媒体へ保全してください。
- JSONは平文です。OSのディスク暗号化と組織が承認した保存先・バックアップを使用してください。同じ媒体だけのバックアップは媒体故障に対応できません。

## 更新・復旧

1. 保存済みを確認して全タブとサーバーを終了し、データフォルダ全体を別の承認済み場所へ保全します。
2. リリース内容と保存形式の互換性を確認します。変更のないソースフォルダで `git pull --ff-only` を実行します。ローカル変更がある場合は上書きせず、別フォルダへ取得してください。
3. `npm ci --ignore-scripts`、`npm run build`、[テスト](TESTING.md)、`npm start` を実行し、まずダミーデータで確認します。
4. 同じオリジンから元のデータフォルダを再選択します。ソース更新でデータフォルダは置換しません。

schemaVersion 1（単一URL）/ 2（複数URL）/ 3（関係者ラベル）に対応します。未知の形式は拒否します。データ形式が非互換の更新には、検証済みの移行手順が必要です。数値だけを書き換えたり、原本を初期化したりしないでください。アプリを旧版へ戻すだけでは、新形式データの互換性は戻りません。

破損時は原本を保全し、正常なバックアップを復元します。アプリ内で復元できない場合は、別の空フォルダに正常なバックアップを `data.json` としてコピーし、そのフォルダを選択して検証します。元のフォルダは削除しません。

起動失敗時はNode.jsの動作、ビルドの有無、4173番の使用状況を確認してください。保存機能が使えない場合はChromeの対応API・フォルダ権限・組織ポリシーを確認します。CSPや端末のセキュリティ制限を解除して対処しないでください。

## セキュリティと利用条件

本番のloopback限定・Host/Origin制限・CSP・JSON検証などを備えていますが、安全性やデータの無損失を保証するものではありません。[SECURITY.md](SECURITY.md) の制約と実機確認事項を確認してください。

実業務での使用には、実ファイル保存・権限失効・再起動・競合の実機試験と、組織のソフトウェア導入・データ保管・外部サービス利用に関する承認が必要です。

プロジェクトのライセンスは未指定です。依存ライブラリにはそれぞれのライセンスが適用されます。
